# tools — проверка подписи без железа и без демона

Тут две вещи: сборка прошивочного кода подписи под ПК и независимый
верификатор транзакции. Вместе они дают цикл «поправил → проверил» за
несколько секунд, не прошивая ESP32 и не отправляя ничего в сеть.

## Сборка и подпись на ПК

```
cd tools/host
make
./signer ../../tx.bin out.bin          # подписать
./signer ../../tx.bin out.bin 4242     # то же с другим сидом ГПСЧ
```

`host/` — это только заглушки платформы (`Arduino.h`, `esp_heap_caps.h`,
`freertos/`) и `main.c`. Сам код подписи берётся из корня репозитория, так
что собирается ровно то, что уйдёт в прошивку.

ГПСЧ детерминированный: один и тот же сид даёт побайтово ту же транзакцию.
Это нужно для отладки — на устройстве случайность берётся из `esp_fill_random()`.

Рядом с `out.bin` кладётся `out.bin.uts` — расшифрованный `unsigned_tx_set`.
Он нужен верификатору: кольцо (публичные ключи и коммитменты остальных
15 выходов) есть только там, в самой транзакции лежат лишь индексы.

## Проверка транзакции

```
cd tools
python3 check_tx.py ../tools/host/out.bin
```

Проверяется:

1. транзакция разбирается целиком, без хвоста;
2. баланс `sum(outPk.mask) + fee*H == pseudoOut`;
3. `key_offsets` соответствуют кольцу из unsigned_tx_set;
4. CLSAG-подпись;
5. Bulletproofs+ range proof;
6. свои выходы (сдача) находятся view-ключом из `../secrets.h`, сумма
   расшифровывается, коммитмент сходится.

Пункты 1–5 — ровно то, что проверяет `monerod`. Если всё зелёное,
`send_raw_transaction` должен принять транзакцию.

Зависимостей нет — только стандартная библиотека Python 3.

## Отладка Bulletproofs+

`bp_reference_prove.py` — эталонный prover на Python. Если BP+ перестанет
сходиться, поднимите в `bp_plus.c` дамп случайных величин (`alpha`, `dL`/`dR`
по раундам, `r`, `s`, `d`, `eta`) и скормите их `prove()`: при одинаковой
случайности прошивка обязана выдавать те же `A`, `L`, `R`, challenges,
`A1`, `B`, `r1`, `s1`, `d1`. Первое расхождение и есть место бага — так были
найдены все ошибки в `bp_plus.c`.

## Откуда взялась уверенность, что верификатор правильный

Он откалиброван на настоящей транзакции из Monero GUI по этому же
unsigned set — `../tx-signed-orig2.bin.pt`. На ней проходят все проверки,
включая CLSAG и BP+. Реализация, которая принимает настоящую транзакцию
Monero и отвергает битую, — это и есть нужный эталон.
